# 喵喵机 OTG 打印 · Android App

**v1.0** ｜ 免驱动，手机 USB OTG 直连就能把 Paperang 喵喵机 / 容大 RP 系列打出来(不一定)。

打印机原本只认官方 App（蓝牙）或 Windows 驱动，本项目把整套私有协议逆向出来，
用 Android 的 USB Host API 直接对打印机的批量端点下发帧数据。
**不需要 root、不需要厂商驱动、不依赖蓝牙。**
**纯粹的vibe coding作品，使用WorkBuddy通过Hy4 preview和DeepSeek V4.1 flash构建**

## 界面导览

顶部是 Material 的 AppBar（品牌蓝），标题在左，**最右边是齿轮图标 —— 所有设置都在那里**。

| 区块 | 内容 |
|---|---|
| **1. USB OTG 设备** | 连接状态、候选设备下拉、重新扫描 / 重新授权 / 查状态、查询机型硬件信息 |
| **2. 机型 / 纸宽** | 打印机型号、纸张宽度、内容居中、每行字节数（可覆盖）、打印浓度、省纸模式、灰度抖动 / 反色 |
| **3. 打印内容** | 文字输入、字号、文字→预览 / 选择图片、**所见即所得预览**（四角圆圈缩放手柄）、适应纸宽、打印预览内容、最小测试 |
| **4. 行宽校准** | 校准页 / 行宽探测 + 四种校准图案（可在设置里隐藏） |

**齿轮设置面板**（展开自动滚到顶部）里是四个即时生效并自动记忆的开关：

- 显示「4. 行宽校准」
- 显示「5. 日志」
- 显示「查询机型/硬件信息」按钮
- **逐行慢速发送**（默认开，见下方说明）

## 支持机型

机型下拉框决定**每行字节数** —— 这是整个 App 里唯一"错了就整幅乱掉"的参数。
数值来源：官方 Windows 驱动 `.xpd` 里的纸张尺寸，按**整数点/mm**（203dpi→8、300dpi→12、200dpi→8）推算，
并与开源实现 paperang-p2-lib（P2 = 72 字节/行）交叉验证一致。

| 机型 | dpi | 打印头点数 | 字节/行 |
|---|---|---|---|
| Paperang P1 / 喵喵机 | 203 | 384 | **48** |
| Paperang P2 / P2S | 300 | 576 | **72** |
| Paperang P3 | 300 | 864 | **108** |
| **Paperang C1**（默认） | 300 | 1248 | **156** |
| Paperang A4 / F1 / F1S | 300 | 2520 | **315** |
| Rongta RP2xx/3xx/4xx 58mm | 200 | 464 | **58** |
| Rongta RP2xx/3xx/4xx 80mm | 200 | 640 | **80** |
| 2寸 57mm 纸 | 203 | 456 | **57** |
| 3寸 80mm 纸 | 203 | 640 | **80** |
| 4寸 110mm 纸 | 203 | 880 | **110** |

> Rongta 另有「连续纸」变体（同点宽，只是纸张类型不同）。
> 若列表里没有你的机器，选最接近的型号再用「每行字节数」手动覆盖，配合第 4 区校准。

## 快速上手

```
① USB OTG 接上打印机 → 自动识别并申请权限（状态栏变绿即成功）
② 选机型（C1 已默认选中）
③ 输文字 → 「文字→预览」，或「选择图片」
④ 在预览里拖动 / 拖角上的圆圈缩放到满意
⑤ 「打印预览内容」
```

卡住了就先点 **「最小测试」**：它发的是打印机固件自带的自检指令，
完全不依赖本端位图。**它出纸 = USB 通道和协议都没问题**，问题在参数或图像；
它不出纸 = 传输层或设备选错了。

## 两个宽度千万别搞混

| | 谁决定 | 作用 | 能不能错 |
|---|---|---|---|
| **打印头宽度** | 机型 | 传输时每行的字节数 | **绝对不能错**，错了整幅错位成"扫描线" |
| **纸张宽度** | 机型选完后单独选 | 只是版式上的内容区，可以比打印头窄 | 随便改，不影响传输 |

选了窄纸之后，内容按窄纸排版，发数据前**补白到打印头行宽**再下发：

```
打印头 C1 = 156 字节（1248 点）
纸宽 80mm = 120 字节（960 点）
→ 补 36 字节的空白，凑够每行 156 字节
```

补白位置由 **「内容在纸上居中」** 开关决定 —— 它同时决定了图像打在打印头的哪个物理位置：

| 勾选 | 补白方式 | 图像落点 |
|---|---|---|
| ✅ 居中 | 左右均分 | **打印头中间** |
| ⬜ 不居中 | 全部留在右侧 | **打印头最左侧** |

> 纸宽 == 打印头宽度时没有补白空间，两种模式物理落点相同，此时开关只影响预览里内容自身的横向对齐。
> 每次打印的日志都会写明落点：`…落在打印头中间` / `…落在打印头最左侧`。

## 所见即所得预览

预览区是自定义 View（`PrintPreviewView`），画的是**真实纸张**：

- 白底矩形 + 蓝色边框 = 纸张
- **底部标注纸宽**（`宽 80.0 mm`，两端带刻度线）
- **右侧竖排标注打印长度**（`长 58.3 mm`，随内容实时变化）
- **内容四角有圆圈手柄** → 拖任意一个角缩放，**对角固定不动**（跟手）
- **单指拖中间** → 挪位置（横向限制在纸内；图比纸宽时可左右取景）
- **双指捏合** → 缩放
- **「适应纸宽」** → 一键恢复到与纸同宽

文字会用当前纸宽重新排版（换纸宽自动重排），所以先用字号滑块定大致字重，再用预览微调。
进场时会自动把示例文字排进预览，不会看到空白。

## 省纸模式（极限打印）

勾选后：

- **打印前不再先吐一段纸**（前置走纸 50 行 → 0），打印头直接开印
- **尾部只留「尾部留白 mm」指定长度**，默认 **5mm**

毫米数按当前机型 dpi 换算成行数：C1（300dpi）5mm = 59 行；203dpi 机型 5mm = 40 行。

不勾选则回到参考实现默认：**前置 50 行 + 尾部 300 行**。日志会写明当次策略。

## 关于「逐行慢速发送」

一帧图像会被拆成若干 ≤1023 字节的 USB 帧连续下发。开启后**每发一行 sleep 15ms**，
把瞬时数据流从"全速灌"降到约 65KB/s。

原因：打印机固件接收缓冲只有几 KB，而手机写 USB 的速率远高于热敏头出纸速率。
一口气灌满会：

- 缓冲溢出 → **丢包、花屏、后半张糊掉**
- 部分低端固件来不及处理，直接**把整条消息截断**

所以默认开启。关掉最快，但只在确认机器缓冲够大、追求速度时才建议关。

## 打出来不对怎么排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 文字由十几根稀疏横线组成、凑起来能认 | 行宽**大于**真机 → 源图被抽稀 | 换正确机型，或用第 4 区「行宽探测」 |
| 整幅斜纹 / 撕裂 / 莫尔纹 | 行宽错 | 同上 |
| 开头一段乱码 / 密集黑线 | 命令态没切干净 | 已在代码里用「等回包 + 静默 250ms」修好；若仍出现请反馈日志 |
| 完全不出纸 | USB 层或设备选错 | 先点「最小测试」；再换候选设备 |
| 后半张糊 / 丢行 | 接收缓冲溢出 | 打开「逐行慢速发送」 |
| 浓度太淡 / 太黑 | 热敏纸差异 | 调「打印浓度」（0-100） |

**第 4 区校准（换机型打出来乱的时候用）**

- **校准页**：按当前行宽打一张图案，判据看 **左/中/右三条竖线**是否笔直连续。
  行宽对→笔直；行宽错→变斜、断、锯齿。
- **行宽探测**：连打 12 段（48 字节对照组 + 基准值 −5…+5，基准取「每行字节数」输入框的值）。
  每段开头有 **n 行黑杠**做标记（全 `0xFF` 的行不受行宽影响，必为黑杠，可靠），靠黑杠粗细数段号。
- 图案可勾选：**45° 棋盘格**（斜向结构，对行宽错位最敏感）、**对勾**（不对称，能看出镜像）、
  **左中右竖线**（锚定绝对位置）、正棋盘格（**默认关**）。

> ⚠️ **正棋盘格不能当判据**：它是周期 2 字节的图案，行宽只要错成偶数倍，它照样显示成规整的
> 竖条/棋盘 —— 看着"正常"其实毫无参考价值。

## 安装与编译

**直接装**：仓库根目录的 `app-debug.apk`，拷到手机安装即可（`minSdk 21`，Android 5.0 以上）。

**自己编译**：需要 JDK 17+ 与 Android SDK（compileSdk 34），仓库自带 Gradle Wrapper。

```bash
cd TsplUsbPrinter
JAVA_HOME=<你的JDK> ./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

> 本机验证过的干净构建方式：`rm -rf app/build .gradle && gradle assembleDebug`。
> 增量构建偶尔会产出尺寸异常的包（打包残留），怀疑产物时请做一次干净构建。

## 项目结构

```
TsplUsbPrinter/app/src/main/java/com/tspl/usbprinter/
├── MainActivity.kt      UI 与全部流程；sendPaperang() 上方有「7 步链路」注释，勿随意改
├── PaperangProtocol.kt  私有帧协议：分帧、CRC32、48 个操作码、回包解析
├── UsbPrinter.kt        USB Host 封装：设备筛选、claimInterface、批量端点读写
├── PrinterModels.kt     机型表（打印头点宽 → 每行字节数）
├── BitmapRaster.kt      Bitmap → 1bpp 行式光栅（MSB 在前、1=黑、逐行紧排）
├── PrintRenderer.kt     文字/自检页排版成 Bitmap
└── PrintPreviewView.kt  所见即所得预览：纸张、尺寸标注、四角缩放手柄
```
